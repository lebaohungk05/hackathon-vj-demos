# Generate EVM Report

Generate the EVM (Earned Value Management) tracker so the PM can track schedule and cost against the plan.

The report is generated by running **`generate_evm.py`** (uses xlwings to preserve conditional formatting).

## Step 1 — Hỏi PM chọn level và cập nhật `WBS_ITEMS` trong `generate_evm.py`

**1a. Hỏi PM muốn theo dõi EVM ở level nào — dùng AskUserQuestion với 4 options:**

```
Câu hỏi: "Bạn muốn EVM theo dõi ở level nào?"
Options:
  Priority mode (with fallback) — recommended → ưu tiên một level, tự động fallback nếu thiếu
  (5) Story only                → chỉ lấy Story; cân bằng, phù hợp đa số dự án
  (4) Epic only                 → chỉ lấy Epic; tổng quan nhất, phù hợp báo cáo cấp cao
  (6) Task/Bug only             → chỉ lấy Task và Bug; chi tiết nhất, phù hợp team nhỏ theo dõi sát
```

**Nếu PM chọn "Priority mode"**, hỏi thêm câu thứ hai với AskUserQuestion (3 options):

```
Câu hỏi: "Bạn muốn ưu tiên level nào?"
Options:
  (1) Epic     → ưu tiên Epic; thiếu level → nhỏ hơn trước (không có gì lớn hơn Epic)
  (2) User Story → ưu tiên User Story; thiếu → nhỏ hơn trước, lớn hơn sau
  (3) Task/Bug → ưu tiên Task/Bug; thiếu → nhỏ hơn trước, lớn hơn sau
```

**1b. Hỏi PM về thời gian và năng lực dự án:**

> "Bạn vui lòng cho biết:
> - Ngày bắt đầu dự án (PROJECT_START): DD/MM/YYYY
> - Ngày kết thúc dự án (PROJECT_END): DD/MM/YYYY
> - Số man-days có thể làm mỗi tuần (CAPACITY_PER_WEEK)? (mặc định: 5)"

Sau khi nhận được, cập nhật 3 hằng số này trong `generate_evm.py` trước khi điền `WBS_ITEMS`.

**1c. Tính `hours` theo level đã chọn:**

| Level | Một row = | hours = |
|---|---|---|
| **Epic** | 1 Epic; Story/Task/Bug mồ côi (không có Epic cha) → include thẳng | Tổng `OriginalEstimate` của tất cả Task/Bug con (qua mọi Story) |
| **User Story** | 1 User Story; thiếu → Task/Bug trước, Epic sau | Tổng `OriginalEstimate` của child Tasks/Bugs trực tiếp |
| **Task/Bug** | 1 Task hoặc Bug; thiếu → Story/User Story trước, Epic sau | `OriginalEstimate` của Task/Bug; nếu fallback Story → tổng Tasks/Bugs con |
| **Epic only** | 1 Epic | Tổng `OriginalEstimate` của tất cả Task/Bug con (qua mọi Story) |
| **Story only** | 1 Story | Tổng `OriginalEstimate` của child Tasks/Bugs trực tiếp |
| **Task/Bug only** | 1 Task hoặc Bug | `OriginalEstimate` của Task/Bug đó |

Với mọi level: **bao gồm items có 0h** (chưa có estimate) — để trống tuần, PM điền sau.

**1c. Cập nhật `LEVEL` và `WBS_ITEMS` trong `generate_evm.py`:**

```python
LEVEL = "user_story"  # epic | user_story | task | epic_only | story_only | task_only  ← đổi theo lựa chọn của PM

# (id, title, hours, assignee)
WBS_ITEMS = [
    # Epic #XXXX [Name] → Story/Epic/Task #YYYY
    (YYYY, "Title", <hours>, "Assignee Name"),
    ...
]
```

Quy tắc chung:
- **Orphaned Tasks/Bugs** (không có parent hoặc parent là Epic): với `epic|user_story|task` → include thẳng theo fallback rule; với `epic_only|story_only|task_only` → exclude và note lại cho PM.
- **Order**: top-down theo cây Epic → Story → Task/Bug trong ADO.
- Cập nhật `PROJECT_START` / `PROJECT_END` / `CAPACITY_PER_WEEK` nếu khác giá trị hiện tại.

**Nếu số items > 29:** script tự động thêm rows vào **output** (không sửa template), logic như sau:
1. Tính số rows cần thêm: `extra = len(WBS_ITEMS) − 29`
2. Trên **tất cả các sheet**, insert `extra` rows ngay trên gray boundary row — cùng số rows và vị trí.
3. Trên sheet `EV (Hoàn thành thực tế)`, `SPI`, `CPI (Chỉ số chi phí)`: copy công thức từ row liền trên vào toàn bộ row mới (cols B → AB) — các sheet này dùng công thức tự tính, phải có đủ rows để auto-calc đúng.
4. Các sheet `PV (Kế hoạch)`, `EV (Tiến độ lũy kế)`, `AC (Chi phí thực tế)`: để trống — script viết PV data bình thường, PM điền EV và AC sau.
5. Cập nhật `MAX_DATA_ROW` theo boundary row mới.

**Nếu dự án kéo dài > 24 tuần:** script tự động thêm cột vào **output** (không sửa template), logic như sau:
1. Tính số tuần cần thêm: `extra = ceil((PROJECT_END − PROJECT_START).days / 7) − 24`
2. Trên **tất cả các sheet**, insert `extra` cột ngay trước cột Tổng (AB).
3. Trên sheet `EV (Hoàn thành thực tế)`, `SPI`, `CPI (Chỉ số chi phí)`: copy công thức từ cột AA sang toàn bộ cột mới (rows 3 → `MAX_DATA_ROW`) — các sheet này dùng công thức tự tính, phải có đủ cột để auto-calc đúng.
4. Các sheet `PV (Kế hoạch)`, `EV (Tiến độ lũy kế)`, `AC (Chi phí thực tế)`: để trống — script viết PV headers/values bình thường, PM điền EV và AC sau.
5. Cập nhật SUM range của cột Tổng trên tất cả sheet: `=SUM(D<row>:<new_last_col><row>)`.

Hằng số liên quan trong `generate_evm.py`:
```python
MAX_WEEK_COL = "AA"  # cột cuối dữ liệu tuần; script tự tính lại khi > 24 tuần
```

## Step 2 — Locate or create the script, then run it

**2-pre. Kiểm tra script trong project hiện tại:**
- Tìm `generate_evm.py` ở **project root** (thư mục gốc của repo đang mở trong IDE).
- **Không tìm ở bất kỳ thư mục nào khác** (không tìm ở `.claude/`, không tìm ở global paths, không tìm ngoài project).
- Nếu file chưa tồn tại → **tạo mới `generate_evm.py` tại project root** với đầy đủ logic theo mô tả bên dưới trước khi chạy.
- Nếu file đã tồn tại → đọc file, cập nhật `LEVEL`, `WBS_ITEMS`, `PROJECT_START`, `PROJECT_END`, `CAPACITY_PER_WEEK` rồi chạy.

```bash
python generate_evm.py
```

The script does the following — **if you ever need to rewrite or create it, implement this logic exactly**:

**2a. Copy template**
`shutil.copy2(TEMPLATE, OUTPUT)` — never edit the template in place.

**2b. Rewrite week headers on ALL sheets, row 2, cols D–(last week col)**
Write `"Tuần N\nDD/MM"` for each week slot starting from `PROJECT_START` on **every sheet** — not just PV. This ensures extra columns (inserted when >24 weeks) also get correct headers on SPI, EV (Hoàn thành thực tế), and other sheets.
After writing, call `sheet.api.Rows(2).AutoFit()` on each sheet to auto-fit the row HEIGHT so both lines ("Tuần N" and date) are fully visible and not clipped.

**2c. Clear ALL data rows 3–31 on every sheet before writing**
The template ships with sample data (e.g. "Phân tích yêu cầu", "Thiết kế hệ thống") in rows 3–31.
**Always clear the full range rows 3–31, never only up to `len(STORIES)`** — otherwise leftover sample rows will appear below your project data.

| Sheet | Col B | Col C | Week cols D:AA | Script action |
|---|---|---|---|---|
| `PV (Kế hoạch)` | Formula `=ROW()-2` — **preserve** | Hardcoded — **clear & write** story title | Hardcoded — **clear & write** planned md | Write C + D:AA |
| `EV (Tiến độ lũy kế)` | Formula → mirrors PV B — **preserve** | Formula → mirrors PV C — **preserve** | Hardcoded sample % — **clear**, leave blank for PM | Clear D:AA only |
| `EV (Hoàn thành thực tế)` | Formula → mirrors PV B | Formula → mirrors PV C | Formula (auto-calc from EV lũy kế × PV) | **Do NOT touch** |
| `SPI` | Formula → mirrors PV B | Formula → mirrors PV C | Formula (auto-calc) | **Do NOT touch** |
| `AC (Chi phí thực tế)` | Hardcoded — **clear & write** | Hardcoded — **clear & write** story title | Hardcoded — **clear**, leave blank for PM | Clear B+C+D:AA; write B+C |
| `CPI (Chỉ số chi phí)` | Hardcoded | Formula → mirrors PV C | Formula (auto-calc) | **Do NOT touch** |

Do **not** touch col AB (Tổng) — it holds `=SUM(D:AA)` formulas. Do **not** touch row 32 (gray boundary) or rows 33–34 (totals).

**2d. Write story titles only where col C is hardcoded (not formula)**
- `PV (Kế hoạch)` col C: write `"#<id> <title>"` for each story (rows 3+).
- `AC (Chi phí thực tế)` col B + C: write No. and title explicitly — AC does not mirror PV via formula.
- All other sheets (EV lũy kế, EV hoàn thành, SPI, CPI): col B/C are formulas that auto-update from PV — do NOT overwrite.

**2e. Fill PV week values on `PV (Kế hoạch)` only**
For each item with `hours > 0`: convert to man-days (`hours / 8`), then spread across week columns using the global `CAPACITY_PER_WEEK` budget. Items with `hours = 0` get no week values — leave blank.
**Round all man-day values to 2 decimal places** before writing to Excel cells (`round(val, 2)`).

**2f. AutoFit columns on PV and AC sheets**
Call `sheet.api.Columns.AutoFit()` on `PV (Kế hoạch)` and `AC (Chi phí thực tế)` after writing all data — these are the only two sheets with hardcoded text that can overflow. Formula sheets do not need this.

**2g. PM fills these after the script runs (in order)**
1. `EV (Tiến độ lũy kế)` D:AA — cumulative % complete per story per week (0.0–1.0).
2. `AC (Chi phí thực tế)` D:AA — actual cost (man-days) per story per week.
3. `EV (Hoàn thành thực tế)`, `SPI`, `CPI` — recalculate automatically.

## Step 3 — Report to PM

Tell the user:
- Path: `assets/EVM_report.xlsx` — thư mục `assets/` nằm ở **project root**, **không phải** trong `.claude/`.
- Which Stories have 0h (tasks not yet broken down — PM should fill estimates before the sprint starts).
- Which orphaned Tasks were excluded and why.
- Like `app-spec.md` / `backlog.xlsx`, this file is a per-project artifact — do not commit it into the shared config base.
